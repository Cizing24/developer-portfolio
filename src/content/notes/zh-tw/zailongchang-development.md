## 先服務地方，再安排網站功能

[在隆昌](https://zailongchang.tw/) 已上線。網站以隆昌的地方品牌為長期主體，整理地方介紹、文化保存、地方服務與合作展覽；單次活動可以有自己的入口，但不取代整個網站的定位。

這個專案讓我練習把「想放很多內容」拆成能維護的資訊架構：訪客先理解地方與品牌，再依需求閱讀文化內容或合作展覽。網站完成上線，也不代表所有文化資料都已整理完成。

## 公開是一組條件

目前原始碼將已發布、公開可見與取得授權分成不同狀態。公開文化查詢需要同時滿足這些條件，而不是只靠前端隱藏連結。

素材也有相同界線：對外照片使用明確發布的圖片網址，不從內部原始檔位置推算公開網址。可保存的資料，和適合對外呈現的資料，是兩件需要分別確認的事。

## 從資料到畫面的路徑

| 層次     | 開發時關注的問題                         |
| -------- | ---------------------------------------- |
| 內容管理 | 草稿、發布與授權如何分開維護             |
| 公開查詢 | 哪些資料真正符合對外條件                 |
| 頁面呈現 | 品牌、地方、文化與合作展覽如何各自清楚   |
| 維運     | 圖片、資料庫與網站如何分工並保留更新空間 |

網站採用 Next.js、TypeScript、PostgreSQL／Prisma 與物件儲存。這篇只整理已核對的開發概念，不公開後台、私人原始碼或基礎設施識別資訊，也不把作品集的場景互動當作原網站的功能。

## 與政府計畫分開記錄

青年村落文化行動計畫是我的個人申請紀錄，另列於[政府計畫筆記](/zh-tw/notes/youth-village-action/)。網站已上線與計畫仍在申請，是兩個不同狀態；計畫中的導覽、培力與文化成果不會被寫成已完成。
