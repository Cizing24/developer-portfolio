## 從排班到管理預約的操作成果

人工排程需要反覆確認服務、人員與時段，還要處理撞期與異動。這個個人實作以 React、Next.js 與 TypeScript 建立顧客預約和店家後台，API 與 PostgreSQL 共同維持多店資料邊界。

1. 店家建立服務與人員，設定營業時間、工作／休息區間及停班日期。
2. 顧客選擇服務、人員與日期，前端查詢可用時段，呈現載入、空值與失敗回饋。
3. 送出時由伺服器重新計算時段，成功後可在店家行事曆查看紀錄。
4. 透過私人管理連結或有權限的後台取消／改期，檢查狀態與 revision，保留異動歷史。

## 核心實作與工程取捨

**React 表單與伺服器資料。** 表單保存服務、人員、日期、時段與送出狀態，透過 API 查詢日期與空位；服務異動需同步更新可選人員與時段。錯誤與重試有明確畫面回饋，預約結束時間和價格仍由伺服器推導。

**看到空位，不等於保留成功。** 建立預約時先取得 Tenant row lock，再讀設定與占用；PostgreSQL 的 partial GiST exclusion 另外禁止有效占用區間重疊。代價是同店寫入序列化，未量測前不宣稱特定吞吐量。

**重試與跨店存取是不同問題。** 店家內的冪等鍵與請求 hash 處理回應遺失後重送；伺服器 Session、Membership 授權與 tenant-scoped 查詢處理跨店存取。複合外鍵與 SQL 約束保護關聯，並未實作 PostgreSQL RLS。
